# 포트폴리오 기술 정리: NodeMacro (Node-based Automation Engine)

## 사용 기술스택
- Language: Python 3.10+
- GUI Framework: Dear PyGui (GPU-accelerated Node Editor)
- Automation: PyAutoGUI, Pynput (Global Event Listening)
- Computer Vision: OpenCV, NumPy, Pillow (Image Recognition)
- Data Management: JSON (Workflow Serialization)

---

## 프로젝트에 대한 개요
"비전 인식 기반의 시각적 노드 자동화 엔진"
코딩 지식 없이도 사용자가 직접 노드를 배치하고 연결하여 복잡한 매크로 시나리오를 설계할 수 있는 데스크톱 애플리케이션입니다. 단순한 좌표 클릭을 넘어 이미지 인식과 논리 제어(반복, 조건 분기)를 결합하여 게임이나 반복 사무 작업 등 다양한 환경에서 지능적인 동작을 수행합니다.

---

## 기능 + 문제 + 해결 + 결과

### 1. 노드 기반 비주얼 워크플로우 설계 (핵심 기능)
- 기능: 드래그 앤 드롭으로 동작, 입력, 제어 노드를 연결하여 실행 흐름을 시각적으로 구성.
- 문제: 매크로 로직이 복잡해질수록 텍스트 기반 설정은 전체 흐름 파악이 어렵고 수정 시 실수가 빈번함.
- 해결: Dear PyGui를 활용한 노드 에디터 인터페이스를 도입하여 실행 순서와 논리 구조를 그래프 형태로 시각화.
- 결과: 복잡한 조건문과 반복문이 포함된 시나리오도 한눈에 파악 가능하며, 노드 간 연결 수정만으로 로직을 즉시 변경할 수 있는 직관적 환경 구축.

### 2. 고정밀 이미지 인식 및 좌표 보정
- 기능: 화면 내 특정 이미지를 탐색하여 좌표를 획득하고, 해당 지점에 대한 클릭이나 이동 수행.
- 문제: 캡처된 이미지의 중심점만 클릭할 수 있어, 이미지 내 특정 위치(예: 버튼의 모서리나 텍스트 영역)를 정밀하게 조작하기 어려움.
- 해결: 이미지 노드 내에 시각적 오프셋 설정 기능을 구현하여 캡처본 위에서 실제 클릭 지점을 십자선으로 직접 지정할 수 있도록 개선.
- 결과: 이미지 인식 후 추가적인 좌표 계산 없이도 픽셀 단위의 정밀한 조작이 가능해져 자동화의 정확도와 성공률을 대폭 향상함.

### 3. 멀티스레딩 기반 실행 엔진 및 비상 정지 (안정성 개선)
- 기능: 설계된 노드 그래프를 순차적으로 실행하며, 긴급 상황 시 즉각적으로 동작 중단.
- 문제: 이미지 검색이나 대기 시간(Wait) 로직이 메인 UI 스레드에서 동작할 경우 화면이 멈춰 사용자가 중단 버튼을 누를 수 없는 프리징 현상 발생.
- 해결: threading 모듈을 사용하여 실행 엔진을 별도 스레드로 격리하고, pynput 전역 리스너를 통해 ESC 키 입력 시 실행 스레드를 즉시 안전 종료하는 패닉 스탑 시스템 구축.
- 결과: 매크로 실행 중에도 실시간 상태 모니터링 및 UI 조작이 가능하며, 예기치 못한 상황에서 즉각적인 제어권 확보로 시스템 안정성 강화.

### 4. 확장성을 고려한 레지스트리 기반 아키텍처 설계
- 기능: 다양한 종류의 입력(마우스, 키보드) 및 제어(반복, 조건) 노드 지원.
- 문제: 초기 개발 시 노드 타입별로 조건문을 사용하여 처리하면서, 새로운 기능을 추가할 때마다 여러 파일을 동시에 수정해야 하는 유지보수 결함 발생.
- 해결: 모든 노드가 공통 인터페이스를 상속받는 객체 지향 구조로 설계하고, 중앙 집중형 레지스트리(NODE_MAP) 패턴을 도입하여 동적으로 노드를 생성 및 관리하도록 리팩토링.
- 결과: 새로운 자동화 기능을 노드 클래스로 정의하고 레지스트리에 등록만 하면 기존 코드 수정 없이 즉시 시스템에 통합되는 높은 확장성 확보.

## 예상 면접 질문 및 답변 (Q&A)

질문 1: 많은 GUI 라이브러리 중 Dear PyGui를 선택한 이유는 무엇인가요?
답변: Dear PyGui는 GPU 가속을 사용하기 때문에 수백 개의 노드와 링크가 포함된 복잡한 그래프 환경에서도 매우 부드러운 성능을 보여줍니다. 특히 내장된 노드 에디터 위젯이 강력하여, 별도의 저수준 캔버스 조작 없이도 고성능 비주얼 프로그래밍 환경을 빠르게 구축할 수 있었기 때문입니다.

질문 2: 이미지 인식 성능과 정확도를 높이기 위해 어떤 전략을 사용했나요?
답변: 단순히 전체 화면을 검색하는 대신, 사용자가 탐색 영역(ROI)을 지정할 수 있는 기능을 추가하여 연산량을 줄였습니다. 또한 OpenCV의 템플릿 매칭 알고리즘을 활용하고 임계값(Threshold) 조절 기능을 제공하여, 미세한 색상 차이나 환경 변화에도 사용자가 직접 감도를 최적화할 수 있도록 설계했습니다.

질문 3: 멀티스레딩 환경에서 UI 업데이트와 실행 상태 공유는 어떻게 처리했나요?
답변: 실행 스레드와 UI 스레드 간의 직접적인 충돌을 피하기 위해 상태 관리 객체를 별도로 두었습니다. 실행 엔진이 현재 상태(실행 중인 노드 정보 등)를 업데이트하면, UI 스레드는 Dear PyGui의 콜백 시스템을 통해 안전하게 해당 정보를 읽어와 화면 오버레이에 표시하도록 구현하여 스레드 안정성을 확보했습니다.

질문 4: JSON 직렬화 시 이미지 자산의 경로는 어떻게 관리했나요?
답변: 매크로 시나리오가 다른 환경에서도 동작할 수 있도록 상대 경로 시스템을 도입했습니다. JSON 파일이 저장되는 폴더 내에 images 폴더를 자동 생성하여 사용된 이미지를 복사해 넣고, JSON 내에는 해당 폴더를 기준으로 한 상대 경로를 기록하여 프로젝트 폴더 자체를 이동하더라도 무결성이 유지되도록 설계했습니다.

질문 5: Undo/Redo 기능 구현 시 메모리 관리는 어떻게 고려했나요?
답변: 전체 노드 에디터의 상태를 캡처하는 스냅샷 방식을 사용하되, 메모리 과부하를 방지하기 위해 최대 히스토리 개수를 제한(30개)하는 링 버퍼 구조를 적용했습니다. 이를 통해 사용자에게 충분한 복구 기회를 제공하면서도 애플리케이션의 메모리 점유율을 일정 수준 이하로 유지할 수 있었습니다.

## 기타 구현 기능
- Undo/Redo 시스템: 사용자의 편집 실수를 복구하기 위한 스택 기반 스냅샷 기능.
- 노드 복사 및 붙여넣기: 클립보드 기능을 구현하여 반복적인 노드 구성을 빠르게 복제 가능.
- 화면 캡처 및 영역 선택 도구: Tkinter 오버레이를 활용하여 직관적인 이미지 캡처 및 탐색 영역 설정 UI 제공.
- 데이터 직렬화: 설계된 전체 워크플로우를 JSON 파일로 저장하고 불러올 수 있는 영속성 지원.
